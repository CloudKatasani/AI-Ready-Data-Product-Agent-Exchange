## 2. File layout

```
packs/utilities/
  pack.yaml                 # identity, company, locale, asOf, seed, regions, overridables, home config
  domains.yaml              # domains, conformed backbone entities & links, canonical entities
  controls.yaml             # control library (regulatory/policy), jurisdictions
  personas.yaml             # 5 personas
  policies.yaml             # sensitivity tags, masking policies, row-access policies, initial grants
  warehouse/
    sources.yaml            # Bronze tables: columns + generator specs + planted patterns + noise
    silver/*.sql            # CREATE OR REPLACE TABLE CURATED_SILVER.X AS SELECT … FROM RAW_BRONZE…
    gold/*.sql              # star schema builds
    dq/*.yaml               # executable DQ rules per object (SQL assertion + dimension + threshold)
  semantic/*.yaml           # semantic views (Snowflake semantic view YAML superset)
  kpis.yaml                 # KPIs: id, name, definition, formula, unit, direction, target range, term, metric, product(s)
  glossary.yaml
  context/
    instructions.yaml       # per agent: persona/response/guardrail/orchestration, versioned
    rules.yaml              # BR-xxx business rules (with machine-applicable `apply` blocks)
    verified_queries.yaml   # VQ-xxx: question + MetricQuery (+ display SQL rendered at build)
    synonyms.yaml
    docs/*.md               # policy/procedure documents for search grounding
  products/DP-UTL-00N.yaml  # data product definitions incl. lifecycle seed + certification script
  agents/AG-UTL-00N.yaml    # domain agent manifests
  scenarios.yaml            # golden scenarios (question, paraphrases, MetricQuery, answer template, expected)
  incidents.yaml            # incident templates + effects
  knockout.yaml             # flagged KPIs + naive formulas + expected deltas
  value.yaml                # value cases per product
  demand.yaml               # seeded requests, demand items
  readiness.yaml            # optional overrides, presets labels
  stories.yaml              # optional overrides for story cue cards (step id → text)
  golden.json               # GENERATED by `pnpm golden` — expected results; committed; reviewed in PR
```

Shared across packs: `packs/_shared/rubrics.yaml` (all thresholds/weights), `packs/_shared/lifecycle.yaml`
(stage overrides, if any), `packs/_shared/stories.yaml` (the 6 standard stories), `packs/_shared/adversarial.yaml`.

### 3.2 `warehouse/sources.yaml` (generator vocabulary — §5)
```yaml
tables:
  - name: OMS_OUTAGE_EVENTS
    system: OMS
    rows: { S: 4000, M: 40000, L: 400000 }
    cdc_noise: { duplicate_updates_pct: 3, deletes_pct: 0.5, dirty_strings_pct: 4, late_arrivals_pct: 1 }
    columns:
      - { name: outage_id, type: VARCHAR, gen: { seq: { prefix: "OUT-", pad: 7 } } }
      - { name: feeder_id, type: VARCHAR, gen: { fk: { table: GIS_FEEDERS, column: feeder_id, dist: zipf, s: 1.1 } } }
      - { name: start_ts, type: TIMESTAMP, gen: { datetime: { from: 2024-01-01, to: asOf, seasonality: { month: [1.3,1.2,1.0,0.9,1.0,1.2,1.5,1.6,1.3,1.0,1.0,1.2] } } } }
      - { name: duration_min, type: INTEGER, gen: { lognormal: { mu: 4.4, sigma: 0.9, min: 1, max: 4320 } } }
      - { name: customers_affected, type: INTEGER, gen: { lognormal: { mu: 5.2, sigma: 1.1, min: 1 } } }
      - { name: cause_code, type: VARCHAR, gen: { choice: { values: [VEG, EQUIP, WEATHER, ANIMAL, PLANNED, UNKNOWN], weights: [24,22,28,9,10,7] } } }
      - { name: major_event_day, type: BOOLEAN, gen: { bernoulli: 0.04 } }
      - { name: crew_notes, type: VARCHAR, gen: { template: "{cause_code} on {feeder_id}" }, tags: [] }
    plant:                                   # patterns the golden questions are meant to find
      - id: P-UTL-01
        description: "Feeder F-2207 in East has 3x outage minutes from vegetation in Q3 2026"
        where: { feeder_id: F-2207 }
        window: { from: 2026-07-01, to: 2026-09-30 }
```

### 3.3 `semantic/reliability.yaml`
```yaml
name: RELIABILITY
description: Distribution reliability indices (IEEE 1366)
tables:
  - { alias: o, fqn: CONFORMED_GOLD.FCT_OUTAGE, pk: outage_key }
  - { alias: f, fqn: CONFORMED_GOLD.DIM_FEEDER, pk: feeder_key }
  - { alias: d, fqn: CONFORMED_GOLD.DIM_DATE, pk: date_key }
relationships:
  - { from: o.feeder_key, to: f.feeder_key }
  - { from: o.date_key, to: d.date_key }
dimensions:
  - { name: region, expr: f.region, synonyms: [territory, area], term: GT-UTL-REGION }
  - { name: feeder, expr: f.feeder_id, synonyms: [circuit] }
  - { name: cause, expr: o.cause_code, synonyms: [outage cause] }
time_dimensions:
  - { name: outage_date, expr: d.date, default: true }
facts:
  - { name: customer_minutes, expr: o.duration_min * o.customers_affected }
metrics:
  - name: saidi
    label: SAIDI
    expr: SUM(o.duration_min * o.customers_affected) / MAX(f.customers_served_total)
    unit: minutes
    decimals: 1
    synonyms: [outage minutes per customer, average interruption duration]
    term: GT-UTL-SAIDI
    default_filters: [ { rule: BR-UTL-012 } ]   # exclude major event days
    naive_expr: AVG(o.duration_min)            # used by Knockout when Semantic is off
products: [DP-UTL-002]
```

## 4. Lifecycle content

`domains.yaml`, `controls.yaml`, and each product file give ADPM's blueprint generator
(`src/lib/packs/blueprint.ts`, ported) enough to synthesise all 25 artifacts for seeded products.
Products marked `IN_DEVELOPMENT` stop at `seed_stage` (default 6) with **open agent proposals** so the
lifecycle story has live work to show.

## 5. Synthetic data generator (`src/lib/warehouse/generate/`)

Generator primitives (TS port of marketplace `seed/synthetic/framework.py` ideas):

| Primitive | Params |
|---|---|
| `seq` | prefix, pad, start |
| `choice` | values, weights |
| `bernoulli` | p |
| `uniform` / `normal` / `lognormal` / `poisson` | params, min/max clamp, decimals |
| `datetime` / `date` | from, to (`asOf` keyword), seasonality (month/weekday multipliers), business hours |
| `fk` | table, column, dist (`uniform`/`zipf`), s |
| `template` | string with `{column}` refs |
| `person` / `company` / `address` / `email` / `phone` | locale-aware from bundled name lists (no faker network) |
| `formula` | expression over prior columns (safe evaluator; no `eval`) |
| `derive_from` | lookup from a parent row (e.g. region from feeder) |

Rules:
- RNG: `mulberry32` seeded by `hash(pack.seed, table, column)` (port `src/mock-snowflake/rng.ts`).
- Generation order is topological on `fk`; rows written via DuckDB Appender in batches of 10K.
- `plant` adjustments applied after base generation, deterministic.
- `cdc_noise` produces Bronze-only artefacts (duplicate `U` rows, `D` tombstones, dirty strings) that
  Silver SQL must clean — so Compare/Knockout show real differences.
- Build time budget: scale M, one deep pack ≤ 25 s on a laptop; cached by content hash of pack.

## 6. Scenario pattern taxonomy (from AI-Ready; every deep pack covers all 15)

1 single KPI value · 2 KPI vs target · 3 KPI by dimension · 4 trend over time · 5 top-N ranking ·
6 contribution/driver · 7 period-over-period change · 8 distribution/percentile · 9 cohort/segment
compare · 10 rule-sensitive (business rule changes answer) · 11 synonym/jargon resolution ·
12 masked-data request (persona-dependent) · 13 row-filtered request · 14 not-certified product ·
15 out-of-scope → decline/redirect.

## 7. Pack validator (`pnpm pack:validate [id]`)

Fails the build on any error. Target ≥ 500 checks per deep pack. Categories:
1. **Schema** — every file parses against Zod; ids unique and correctly prefixed.
2. **Referential** — every term/metric/product/agent/KPI/rule/VQ/persona reference resolves.
3. **Quotas** — §1 depth quotas.
4. **Warehouse** — Silver/Gold SQL executes; every semantic table/column exists; every metric compiles
   and returns a non-null value; DQ rules execute.
5. **Semantics** — every KPI maps to a metric; every metric has a glossary term; CDE columns have DQ rules.
6. **Governance** — every sensitive column has a tag; Certified products have masking on all sensitive
   output columns; every persona has ≥1 entitlement; archetype A has a row filter.
7. **Scenarios** — every scenario compiles; pattern coverage 1–15; expectations hold; KPI values fall
   inside `kpis.yaml` target ranges ±; persona expectations hold.
8. **Agents** — coverage ⊆ bound products' semantic metrics; every production agent ≥ 4 scenarios;
   eval thresholds achievable in scripted mode (run eval).
9. **Stories** — every story step's target (product, agent, scenario, incident) exists in the pack.
10. **Domain-string lint input** — emits the term list used by invariant 1's lint.
11. **Golden drift** — regenerated golden equals committed `golden.json` (or `--update` with review).

## 8. Converting predecessor content (Phase 1 & 10 checklist per pack)

1. From AI-Ready `src/packs/<id>/`: copy company, personas (add archetype E), glossary, context
   (instructions/rules/verified queries/synonyms/docs), KPIs + ranges, products (map 6 → 8 by adding
   1 IN_DEVELOPMENT and 1 more Certified), agents (4 → 5), scenarios (15 → ≥ 20; convert `run()` logic
   into `MetricQuery` + rule `apply` blocks), incidents, impact presets. Convert per-table row
   generators into `sources.yaml` specs; re-express transforms as SQL.
2. From ADPM `packs/<id>.yaml`: domains, conformed backbone, controls, sample decisions → product
   `decision`, platform profiles (Build Guide), glossary additions, seed products not yet present
   (as Draft or as demand items).
3. From Marketplace `manifests/`: agent manifest fields (coverage, guardrails, budgets, out-of-scope),
   KPIs not yet present, value cases, curated demo exchanges → additional scenarios.
4. Run validator; run `pnpm golden --pack <id> --update`; review numbers for plausibility (a reviewer
   checklist lives in `tests/golden/REVIEW.md`).
